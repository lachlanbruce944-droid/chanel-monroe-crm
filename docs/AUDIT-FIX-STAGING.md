# Website and CRM staging checks

1. Prepare isolated Supabase staging with the project's existing schema and migration ledger. Explicitly provision the named staff owner before applying the reservations migration. Point the staging frontend at staging, use a test mailbox and set the database setting `app.enquiry_receipt_url` to the staging enquiry-email function URL. The scheduled worker skips dispatch while this setting is absent. Verify pg_cron and pg_net are available.
2. Apply the two new migrations and deploy the website's enquiry-email and CRM's Stripe functions in staging. Configure `CRM_STRIPE_MODE=test` with matching Stripe test credentials and webhook signing secret. Keep the existing production provider and DNS settings until release approval.
3. Submit two overlapping synthetic requests including the buffer. Confirm that one can reserve the slot. Test a 48-hour-old unreviewed hold, two adjacent intervals, a staff timing edit and restoring a reclaimed appointment. Run the competing requests from separate connections.
4. Close the browser after submission and verify the receipt worker dispatches the queued ID through the test mailbox. Force a mail failure, then clear it. Repeat the same enquiry ID and confirm that only one intake and booking exist. Review possible matching clients before merging. Verify that the approved staff user can open the attached synthetic selfie and the browser recap is absent after reload.
5. Review a synthetic A$1,000 quote with a A$300 deposit, cancel review once, then approve and pay in Stripe test mode. Staff confirms the booking explicitly. After A$80 of agreed extras, verify the final invoice is A$780. Replay the Stripe test event and confirm only one payment is recorded. Verify void and out-of-band status in CRM before release.

The scheduler retries undelivered receipt requests inside the provider idempotency window. A public intake that cannot create its linked booking rolls back, so the client can retry the same request. Existing attached media is read via the private bucket. Submission-bound upload tickets and abandoned upload cleanup are separate work.
